# 用户模型折扣

用户模型折扣只存储在 `user_model_pricings` 独立表，未配置规则时按原价计费。所有改价操作必须经过 `ReplaceUserModelPricingContext`，直接修改数据库会绕过版本协议。

## 缓存与一致性

Redis 可用时，每次请求用一次 MGET 校验独立定价版本，再复用进程内完整快照。快照最多缓存 256 个用户，绝对有效期 30 秒；空规则同样缓存，并返回副本供请求冻结使用。多节点必须连接同一个 Redis，且一致启用 Redis。Redis 未启用、版本缺失或故障时查询数据库；数据库查询失败则返回错误，不能回退为原价。

改价事务先建立 120 秒版本屏障，屏障发布失败则回滚。提交后由下一次持有用户锁的回源发布已提交版本；事务回滚遗留的屏障只会暂时增加回源，过期后恢复。版本发布与快照读取在同一用户锁内完成，避免迟到的回源重新发布旧版本。SQLite 的缓存回源通过不改变版本值的更新获取写锁，兼容 WAL 模式。

回源与管理读写继承请求 Context，并有 5 秒总预算，单次 Redis 操作最多 1 秒。同版本的并发回源用 singleflight 合并。发起请求取消后，仍有预算的等待请求最多重试一次。正常请求不续期本地快照，慢查询也不延长旧快照寿命。

## 数据库升级

升级时停止旧版本应用写入，再运行自动迁移：增加并回填模型名的 SHA-256 `model_key`，使用 `(user_id, model_key)` 唯一索引替换旧索引，使 MySQL、PostgreSQL、SQLite 都保留模型名的大小写语义。回填按批读取并在事务内更新；旧索引在回填成功后删除，失败可以重启重试。新增规则通过 GORM 创建钩子统一生成键。

## 编辑会话

管理弹窗按一次打开会话固定规则、模型列表和 revision。后台刷新不会覆盖草稿；保存遇到 409 会保留编辑内容，重新打开才载入最新规则。

缓存减少完整规则集的数据库读取，不代表已通过亿次日请求容量验证。部署容量仍需按峰值并发、规则数量、Redis 延迟、数据库余额写入和日志吞吐压测。

MySQL/PostgreSQL 的真实数据库回归、HTTP 定价负载和最终扣费对账命令见 [实测工具说明](../tools/pricing-load/README.md)。最终扣费回归覆盖钱包、订阅、流式、改价快照及多用户并发；本机生成的运行数据与报告不纳入版本控制。

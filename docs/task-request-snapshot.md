# 视频任务请求快照开发文档

## 1. 目标与范围

为视频生成任务保留一份可审计、可排障的用户请求体快照。快照用于查看用户实际提交的模型、提示词、时长、分辨率、内容项和素材引用，不用于重放请求，也不替代任务轮询数据。

本功能覆盖所有经过统一任务提交链路创建的视频任务，包括原生视频接口、Videos/Responses 兼容入口和任务插件入口。判断依据是统一任务动作和平台能力，不写死某一个供应商名称，后续新增视频插件可以复用。

本功能不保存请求头、API Key、渠道密钥、Cookie、上游响应、上游任务数据或原始媒体文件。请求体中的 Base64 内容只保留字段位置和占位信息，不保留可还原的字符内容。

## 2. 当前代码边界

视频插件提交阶段已经把用户请求解析为 task_request，并在 submitContext 中提供给插件。任务落库时：

- Task.Data 保存插件返回的轮询数据，用于查询和结算。
- Task.PrivateData 保存上游任务 ID、计费快照、插件状态等内部数据。
- 任务轮询会更新任务行，任务列表为了性能会省略部分大字段。

因此请求体不能塞进 Task.Data 或 Task.PrivateData。否则每次轮询都会携带或重写请求体，任务列表和数据库 IO 会随着请求体变大而放大。

## 3. 存储设计

新增主库表 task_request_snapshots，每个任务最多一条记录：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| task_id | bigint，唯一索引 | 主库 tasks.id，用于内部关联 |
| public_task_id | varchar(191)，索引 | 对外任务 ID，避免详情查询依赖内部 ID |
| user_id | int，索引 | 权限校验和用户查询 |
| platform | varchar(30) | 任务平台 |
| model | varchar(191) | 用户请求中的模型名 |
| body | long text | 脱敏后的 JSON 请求体 |
| body_bytes | bigint | 脱敏后字节数 |
| base64_omitted | boolean | 是否移除了 Base64 内容 |
| truncated | boolean | 是否发生大小截断 |
| created_at | bigint，索引 | 快照创建时间 |

MySQL 使用 LONGTEXT，PostgreSQL 和 SQLite 使用 TEXT，通过 GORM 的自定义数据类型保证三种数据库的容量语义一致。快照设置应用层大小上限，避免无限制写入。

任务先按现有流程在主库落库，任务 durable 后再独立写入快照。独立日志库不参与这次写入；请求快照本身不写入独立日志库，也不影响计费日志的投递和结算。这样快照表故障不会让已经提交到模型服务的任务失败或重复退款。

### 配置

功能默认开启。管理员可在“系统设置 → 运维 → 日志维护”修改“保存视频请求体”开关，保存后当前实例立即生效，其余实例通过现有配置同步周期更新。开关保存在主库 options 表，重启后恢复；已有数据库设置优先于环境变量默认值。环境变量仍可设置初始开关和容量边界：

~~~text
TASK_REQUEST_SNAPSHOT_ENABLED=true
TASK_REQUEST_SNAPSHOT_MAX_BYTES=262144
TASK_REQUEST_SNAPSHOT_MAX_DEPTH=16
TASK_REQUEST_SNAPSHOT_MAX_ITEMS=1000
TASK_REQUEST_SNAPSHOT_WRITE_TIMEOUT_MS=500
~~~

环境变量边界配置变更后需要重启实例，网页开关无需重启。关闭后新进入快照构建阶段的视频任务不执行脱敏、序列化和快照 INSERT；已经构建的在途快照仍可完成写入，历史快照不会被删除。快照 INSERT 使用脱离客户端取消信号的独立超时，默认 500 毫秒，允许配置范围为 1 到 5000 毫秒；超出范围时回退到 500 毫秒。超时只放弃快照写入，不改变已经持久化任务的结算结果。

## 4. 脱敏规则

### 4.1 Base64

递归遍历对象和数组：

- 以 data: 开头且 MIME 参数包含 base64 的字符串替换为 [base64 content omitted]。
- 字段名为 base64、image_base64、video_base64、audio_base64 或以 _base64 结尾的字符串替换为同一占位符。
- 在 image、video、audio、media 或 data 等媒体字段中的原始 Base64 字符串也替换为同一占位符；普通 HTTP URL、asset:// 引用和提示词文本保留。
- 不解码、不计算原文哈希、不把原文写入日志。
- 保留字段位置和 JSON 类型，确保管理员能看出请求使用了哪一种输入媒体。
- 二进制字节切片也统一替换为占位符，避免 JSON 编码器将其转成另一种 Base64 表示。

例如：

~~~json
{
  "content": [
    {
      "type": "image_url",
      "image_url": {"url": "[base64 content omitted]"}
    }
  ]
}
~~~

### 4.2 敏感字段

请求体中出现 api_key、access_token、authorization、cookie、password、secret、token 等凭证字段时保存 [redacted]。这属于服务端保护，即使调用方误把凭证放入 JSON，也不会进入快照表或详情响应。

HTTP/HTTPS 素材 URL 中的 signature、credential、access_key、api_key、token、secret、password 和 authorization 查询参数会替换为 [redacted]；普通路径和非敏感查询参数保留。

### 4.3 大小和深度

- 设置最大快照字节数、最大嵌套深度和最大数组／对象项数。
- 超过嵌套深度或集合项数时，具体值替换为 [omitted: too_large] 并将 truncated 置为 true。
- 脱敏后的整体 JSON 仍超过最大字节数时，保存合法的截断标记对象并将 truncated 置为 true，不保存超限请求的其他原文。
- Base64 内容通过前缀或字段名判断，不解码，避免大媒体造成额外 CPU 和内存峰值。
- 脱敏后的 JSON 必须仍然是合法 JSON；不能通过截断原始字节制造半个 JSON。

## 5. 写入和读取流程

### 5.1 创建任务

1. 统一任务入口完成鉴权、模型校验、计费预估和上游提交。
2. 上游提交成功并形成任务对象后，从用户解析请求体生成脱敏快照。
3. 任务行成功落库后写入快照，快照只增加一次独立 INSERT。
4. 快照写入失败时记录告警并继续任务结算；不能因为诊断快照故障破坏已经受理的视频任务。

快照生成只执行一次。任务重试上游渠道时不生成多份快照，也不保存重试渠道的请求头或密钥。

### 5.2 查询

任务列表不 JOIN task_request_snapshots，不在列表响应中带请求体。单任务详情通过独立查询按任务 ID加载，并先校验用户归属；管理员可以查看授权范围内的任务。

请求快照读取失败不能影响任务状态、视频结果或计费结算，详情接口应返回明确的“快照不可用”状态，不伪造空请求体。

管理控制台和用户会话可以按需调用 GET /api/task/:task_id/request 获取单个任务快照。普通用户只能读取自己的任务，管理员可以读取唯一匹配的任务；任务列表不会携带 body，也不会 JOIN 快照表。历史任务或关闭功能期间创建的任务可能没有快照，接口会返回快照不存在。

## 6. 性能设计

开启功能后每个视频任务增加一次有界的脱敏遍历、一次 JSON 序列化和一次主库 INSERT。这是保存数据不可避免的成本。

为避免影响持续轮询：

- 请求快照不写入 tasks 行。
- 轮询更新不读取、不更新快照。
- 任务列表不 JOIN 快照表。
- 快照只有在用户打开单任务详情时读取。
- 快照大小、深度和集合数量均有限制。
- 脱敏器在遍历阶段也限制预计输出预算，避免超大普通字符串先完整参与 JSON 序列化。
- 可以通过系统设置关闭快照保存，关闭后不执行脱敏和 INSERT。

不采用无保障的后台 goroutine 作为唯一写入方式。异步写入虽然可以减少创建请求的尾延迟，但进程退出、队列满或数据库短暂异常时会丢失快照。当前实现优先保证已经受理的视频任务和计费链路，快照生成或写入失败只告警并留下“快照不存在”的可识别结果。

## 7. 失败语义

| 场景 | 行为 |
| --- | --- |
| 脱敏失败 | 任务继续按现有流程落库和结算，记录告警，详情接口返回快照不存在 |
| 快照 INSERT 失败 | 任务保持成功受理，记录告警，详情接口返回快照不存在 |
| 快照查询失败 | 只报告快照不可用，不改变任务状态和费用 |
| Base64 输入 | 任务正常提交，快照只保存占位符 |
| 请求体超过上限 | 保存合法的截断快照并标记 truncated |
| 兼容接口请求 | 保存兼容入口收到的用户请求结构，不保存转换后的上游结构 |

## 8. 测试与压测

### 行为测试

- JSON、嵌套数组、媒体对象和多个 Base64 data URI。
- Base64 字段名识别、凭证字段脱敏、普通长文本保留。
- 深度、项数和总字节数上限。
- 任务成功、失败、上游重试、即时终态和异步终态。
- 列表接口不加载快照，详情接口按归属读取。
- 快照写入失败时任务和结算不受影响，详情接口返回快照不存在。

### 数据库测试

在 SQLite、MySQL 和 PostgreSQL 上分别验证：

- 空数据库迁移。
- 已有任务数据升级。
- 应用连续启动两次，迁移幂等。
- 唯一约束和索引有效。
- 长文本字段容量和 JSON 内容可读取。

### Mock 压测

使用本地 mock 上游，不产生真实视频任务。至少包含：

- 关闭快照和开启快照两组基线。
- 200 个逻辑用户、64 个并发提交者。
- 成功、失败、Base64、大请求、快照写入失败和任务查询混合场景。
- 记录吞吐、p50/p95/p99 延迟、错误率、CPU、内存、主库连接数和每任务数据库写入次数。

验收不是要求“零开销”，而是确认快照开启后任务轮询延迟和错误率没有异常放大，列表查询不随快照体积增长，且新增一次写入的成本符合预期。

## 9. 本次实现验证

- 定向 Go 行为、控制器和路由测试通过。
- MySQL 8 和 PostgreSQL 15 通过创建表、重复迁移、任务落库后快照写入、读取和清理。
- 200 个逻辑用户、64 个并发 worker 的脱敏 mock 压测通过，200/200 成功，Race 检测通过。
- SQLite 持久化 mock 压测通过，200/200 任务和 200/200 快照写入成功，Race 环境吞吐约 140 个任务/秒。
- 脱敏 benchmark 约 9.2 微秒/次、11.5 KB 分配、32 次分配；关闭快照开关时 0 分配。
- 完整 Go 回归中，controller 包的 SQLite 并发夹具在并行执行时出现既有锁时序失败，单独重跑和串行包执行通过；relay/channel 的 HTTP/2 graceful GOAWAY 测试在当前 Windows 主机出现 socket 强制关闭，属于既有网络测试环境问题，与快照路径无关。

这些数字是当前开发机和测试数据库的基线，不是生产容量承诺；上线前应按实际数据库规格重新采样。

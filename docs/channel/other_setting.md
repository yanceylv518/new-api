# 渠道额外设置说明

该配置用于设置一些额外的渠道参数，可以通过 JSON 对象进行配置。主要包含以下三个设置项：

1. force_format
    - 用于标识是否对数据进行强制格式化为 OpenAI 格式
    - 类型为布尔值，设置为 true 时启用强制格式化

2. proxy
    - 用于配置网络代理
    - 类型为字符串，支持 `http`、`https`、`socks5` 和 `socks5h` 协议
    - 保存时必须包含协议和主机；仅允许空路径或根路径 `/`，不允许 query 或 fragment
    - SOCKS 代理未填写端口时，运行时使用默认端口 `1080`

3. thinking_to_content
   - 用于标识是否将思考内容`reasoning_content`转换为`<think>`标签拼接到内容中返回
   - 类型为布尔值，设置为 true 时启用思考内容转换

--------------------------------------------------------------

## JSON 格式示例

以下是一个示例配置，启用强制格式化并设置了代理地址：

```json
{
    "force_format": true,
    "thinking_to_content": true,
    "proxy": "socks5://proxy.example:1080"
}
```

--------------------------------------------------------------

通过调整上述 JSON 配置中的值，可以灵活控制渠道的额外行为，比如是否进行格式化以及使用特定的网络代理。

## 升级兼容性

旧版本会忽略代理地址中的 path、query 和 fragment。为避免升级后中断已有渠道流量，运行时会继续剥离这些遗留后缀，并对同一代理地址每个进程记录一次不含凭证和后缀的警告。该兼容逻辑不会改写数据库；再次保存渠道时必须按上述严格规则修正代理地址。

代理连接使用 30 秒 TCP 拨号超时和 30 秒 KeepAlive；TLS 握手超时为 10 秒。这些超时同样适用于未配置渠道代理的中转请求。

## 视频分辨率路由

Doubao Video 和 Doubao Video（AnyLLM）的渠道编辑页在“路由策略”中提供“视频路由规则”。规则保存在渠道现有的 `setting.video_routing_rules`，不增加数据表。

同一模型的普通渠道可设置“在所选分辨率下跳过此渠道”，选择 `4K`；专用渠道设置“仅在所选分辨率下使用此渠道”，选择 `4K`。两类渠道都需要提供用户请求的模型名，实际上游模型名由各渠道的模型映射决定。

```json
{
  "video_routing_rules": [
    {
      "model": "doubao-seedance-2-0-260128",
      "mode": "deny",
      "resolutions": ["4k"]
    }
  ]
}
```

`allow` 表示仅接受所选分辨率，`deny` 表示排除所选分辨率。不指定分辨率的请求不会进入 `allow` 渠道；未配置规则的渠道沿用原有行为。原模型的规则也适用于该渠道映射到它的别名；显式配置别名规则时，以别名规则为准。

规则读取原生创建接口、`/v1/videos` 和 `/v1/responses` 的 `resolution` 或 `size`，也支持 `metadata` 和视频表单请求。像素尺寸按插件相同规则换算。仅筛选候选渠道，不改写模型、请求参数、价格或折扣；分组权限、素材账号约束、优先级、权重和重试继续生效。Seedream 图片及其他插件不受影响。若全部渠道被排除，则请求失败，不会跨越权限或素材账号限制选择渠道。

## 配置保存

网页保存渠道时，对 `setting` 和 `settings` 仅提交实际编辑字段及读取时的原始配置。服务端合并补丁，保留未知字段和原始数值精度；`null` 表示删除字段，空字符串、`false` 和 `0` 保留明确含义。若配置已被其他操作更新，返回 HTTP 409，需重新加载后编辑。读取无效配置不会清空或写回数据库。

管理接口仍支持原有完整配置提交方式。使用 `setting_patch` 或 `settings_patch` 时，必须分别同时提交 `setting_base` 或 `settings_base`，且不能对同一配置同时提交完整替换和补丁；嵌套对象合并，数组整体替换。

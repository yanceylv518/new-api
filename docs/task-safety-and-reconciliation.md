# 异步任务安全与对账

本文说明异步任务提交、查询和结算的故障处理。适用于任务插件的原生接口及主机兼容接口。

## 提交与恢复

网关在请求上游之前保存提交意图，使用同一个公开任务 ID 交接正式结果。提交请求使用最长五分钟的独立上下文；客户端断开连接不会取消已经开始的提交或直接退还预扣。

提交意图分别保存当前渠道报价与实际预扣总额。重试补扣与预扣记录在同一事务中更新，替换渠道意图时保留资金记录。提交交接或中断恢复会在事务内退还超出当前报价的预扣差额，并同步钱包或订阅、令牌及缓存恢复标记；资金交接完成前不能进行初始记账。

- 上游明确拒绝且提交意图删除成功：按原有策略处理退款和可重试错误。
- 网络响应不确定、上游已返回 2xx 但解析失败、正式结果保存失败：停止自动提交重试，保留任务与预扣，避免重复生成或运营方承担未记录费用。
- 响应解析失败时，最多各保存 1 MiB 的请求和响应恢复证据。恢复仅调用当前插件的响应解析器，不重新提交生成请求。无法保存完整证据或恢复任务 ID 时，该任务保持未结算状态。
- 明确拒绝但本地意图删除失败：保存拒绝证据，恢复后通过原子结算退款。不会同时退款并留下待初始入账的记录。

初始用量统计和待入账标记在主库同一事务内更新，恢复不会重复增加请求数、用户用量或渠道用量。同库消费日志参与该事务，独立日志库使用待投递队列补写。

队列按初始记账和日志投递分类并建立索引，由独立于视频轮询的费用恢复任务处理，各队列每轮最多占用五秒；日志库故障不会阻塞视频轮询。完成且缓存已同步的退款流水保留七天，过期记录本身即可触发分批清理，不依赖新的退款失败。

终态任务确认提交资金后才进入初始记账恢复队列；资金未确认时拒绝记账并报错。启动不扫描历史终态任务补建初始记账记录。

账户有非终态任务、终态任务待初始记账，或未完成退款及其余额缓存同步时，禁止自助注销、管理员删除和硬删除。删除检查、任务意图交接和预扣退款交接共用用户行锁，避免检查后又产生新任务或退款。拒绝删除时保留原会话和令牌；处理完任务及账务后可重新删除。回调转发前从主库检查账户，已停用或删除的账户不再交付回调。

终态任务在资金确认前还没有待记账队列项，删除账户时会额外检查当前用户的终态任务快照。该检查只在删除账户时执行，不触发启动阶段的全站历史扫描。

升级时分批清除待日志队列中的退役人工核实标记；已被旧版本误分类为日志投递的标记也会在投递时清除。清理仅删除该标记的队列项，不调整任务、余额和历史消费记录。

## 查询与结算

查询接口返回 404、410、429、5xx、鉴权错误、网络错误或插件解析错误，都不足以证明生成失败。任务保持非终态和预扣，查询退避从 15 秒递增至最多 300 秒。达到 `TASK_POLL_MAX_FAILURES` 后标记结果未确认，继续保留恢复查询的机会；生成时间超过 `TASK_TIMEOUT_MINUTES` 也不自动退款。旧系统退款迁移边界保持原有不退款行为。

当前加载的插件负责查询和恢复，即使任务创建时使用了旧版本插件。插件更新后应保持对在途任务响应的兼容；解析不兼容时保持结果未确认，不再因查询错误自动退款。

提交时尝试过的渠道按顺序保存在现有任务执行快照中，并写入消费及结算日志的 `admin_info.use_channel`。管理员可在消费日志、任务日志渠道列及任务详情查看重试链路；普通用户不返回该字段。历史记录没有链路快照时不推测或补造重试记录。

所有插件的终态和账务调整共同提交，覆盖钱包、订阅、令牌、渠道和费用快照。数据库失败会回滚终态，保留下一次结算机会；重复终态回包不能重复扣费、退款或写差额日志。用户与令牌按折后金额记账，渠道按折前金额记账。独立日志库仍使用项目已有的差额日志补写机制。

上游删除完成但最终用量未能确认时，网关保留 `UNKNOWN` 任务和预扣；查询无法恢复费用时保持未结算状态。已确认生成失败或取消才自动退款。过期产物链接的长期存储不属于此机制，成功任务的上游链接仍可能过期。

轮询按主键循环游标取有限批次，避免早期慢任务长期占据查询窗口。视频渠道并行数最多 64；同渠道原有查询间隔和 `DisableTaskPollingSleep` 设置继续生效。任务按网关记录 ID 隔离，批量查询按实际提交账号、地址、代理、渠道类型和冻结请求头分组，修改渠道请求头不会切换旧任务的查询身份。

资源归属使用独立索引表，成功任务与资源索引共同提交。插件通过 `resourcePaths` 声明用于查找的结果字段，历史索引在后台按固定上界、每批最多 32 条和持久化检查点补建，完成后不再扫描任务历史。补建完成前，仅凭资源 ID 的请求返回 503；提供 `origin_task_id` 可直接核对指定任务，用户归属、重复记录及原账号校验继续生效。

成功任务同时按提交时冻结的资源路径与当前插件资源路径建索引。插件新增路径后，历史补建已越过但尚未完成的任务仍能建立新索引；插件停用或移除后仍保留冻结路径的索引能力。

## Redis 故障策略

启用 Redis 时，余额缓存可能包含尚未批量落库的预扣。Redis 不可用或余额同步未完成时，鉴权和预扣返回 HTTP 503、错误码 `quota_cache_unavailable`；鉴权响应带 `Retry-After: 5`。不会回退使用可能偏高的数据库旧余额。

故障路径每进程最多每 30 秒输出一次无凭证告警。运维应监控 Redis 可用性及此错误码，恢复缓存连接和待同步记录后再恢复请求。需要高可用时应配置 Redis 故障转移；该策略没有把错误余额回退作为降级选项。

## 任务凭证与升级要求

任务保存实际提交账号，以便渠道更换密钥后仍能查询原任务。新写入的渠道密钥及提交恢复证据使用 AES-256-GCM 加密。部署前必须配置持久的 `CRYPTO_SECRET`，或配置持久的 `SESSION_SECRET` 作为后备来源；所有读取同一任务库的节点必须使用一致的加密密钥。未配置持久密钥时，任务提交会在预扣和上游请求之前拒绝。

历史明文任务仍可读取，下一次写入时自动加密；不对大任务表执行全表回填或新增列。不要在在途任务尚未处理完时直接更换密钥，当前实现没有多密钥轮换机制。回滚至不支持此封装的旧版本前，应处理在途任务并安排相应数据恢复；旧版本无法直接使用已加密的账号凭证。

## 私域素材配额

管理员可在“系统设置 → 安全 → 管理接口限流”中调整图片、视频、音频及客户兼容接口图片的单文件大小，以及每个账号的素材数量和原件容量；账号数量或容量设为 `0` 表示不限制。保存后当前节点立即生效，其他节点按现有配置同步周期更新。单文件限制不改变素材渠道自身的限制；反向代理的请求体上限也需容纳所配置的文件和 multipart 开销。

以下环境变量作为后台尚未保存素材限制时的默认值；后台保存后以数据库配置为准。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `PRIVATE_ASSET_USER_MAX_COUNT` | `1000` | 每个用户跨全部素材组的素材数量上限，`0` 禁用 |
| `PRIVATE_ASSET_USER_MAX_STORAGE_MB` | `1024` | 每个用户保存的原件容量上限，单位 MiB，`0` 禁用 |

素材创建事务再次检查累计配额，同用户不同组并发上传不能各自突破上限。对象大小保存在独立的 `seedance_asset_sizes` 小表，不给现有素材大表新增大小列。历史本地对象没有大小记录时，每个按旧单文件上限 50 MiB 保守计入，避免读取真实 OSS 或回填历史对象。已有素材较多的站点应根据该保守值配置容量，或明确禁用容量限制。

外部链接只计入素材数量，不占本站原件容量。删除原件素材会一起删除大小记录；禁用限制期间仍记录新上传对象的大小，重新启用时可准确计算这些对象。新表迁移可重复执行，升级不修改历史任务金额和已有渠道累计用量。

素材引用在解码后检查归属，包含 JSON Unicode 转义和大小写不同的 `asset://`。不属于调用用户、不可用或没有授权映射的媒体引用会被拒绝。

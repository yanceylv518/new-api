# 异步任务安全与对账

本文说明异步任务提交、查询和结算的故障处理。适用于任务插件的原生接口及主机兼容接口。

## 提交与恢复

网关在请求上游之前保存提交意图，使用同一个公开任务 ID 交接正式结果。提交请求使用最长五分钟的独立上下文；客户端断开连接不会取消已经开始的提交或直接退还预扣。

- 上游明确拒绝且提交意图删除成功：按原有策略处理退款和可重试错误。
- 网络响应不确定、上游已返回 2xx 但解析失败、正式结果保存失败：停止自动提交重试，保留任务与预扣，避免重复生成或运营方承担未记录费用。
- 响应解析失败时，最多各保存 1 MiB 的请求和响应恢复证据。恢复仅调用当前插件的响应解析器，不重新提交生成请求。无法保存完整证据或恢复任务 ID 时，需要管理员核实上游记录。
- 明确拒绝但本地意图删除失败：保存拒绝证据，恢复后通过原子结算退款。不会同时退款并留下待初始入账的记录。

初始用量统计和待入账标记在主库同一事务内更新，恢复不会重复增加请求数、用户用量或渠道用量。初始消费日志沿用项目的尽力写入语义，未引入新的初始日志投递系统。

## 查询与结算

查询接口返回 404、410、429、5xx、鉴权错误、网络错误或插件解析错误，都不足以证明生成失败。任务保持非终态和预扣，查询退避从 15 秒递增至最多 300 秒。达到 `TASK_POLL_MAX_FAILURES` 后标记待对账，继续保留恢复查询的机会；生成时间超过 `TASK_TIMEOUT_MINUTES` 也不自动退款。旧系统退款迁移边界保持原有不退款行为。

当前加载的插件负责查询和恢复，即使任务创建时使用了旧版本插件。插件更新后应保持对在途任务响应的兼容；解析不兼容会进入待核实状态，不再因查询错误自动退款。

所有插件的终态和账务调整共同提交，覆盖钱包、订阅、令牌、渠道和费用快照。数据库失败会回滚终态，保留下一次结算机会；重复终态回包不能重复扣费、退款或写差额日志。用户与令牌按折后金额记账，渠道按折前金额记账。独立日志库仍使用项目已有的差额日志补写机制。

上游删除完成但最终用量未能确认时，网关保留 `UNKNOWN` 任务和预扣；查询不能恢复费用时，需要人工对账。已确认生成失败或取消才自动退款。过期产物链接的长期存储不属于此机制，成功任务的上游链接仍可能过期。

轮询按主键循环游标取有限批次，避免早期慢任务长期占据查询窗口。视频渠道并行数最多 64；同渠道原有查询间隔和 `DisableTaskPollingSleep` 设置继续生效。任务按网关记录 ID 隔离，批量查询按实际提交账号分组。

## 管理员确认最终费用

接口：`POST /api/task/:task_id/reconcile`。

只接受站点所有者的登录会话；不接受普通用户、管理员角色或个人访问令牌。请求必须使用 JSON，同源浏览器请求，并附带绑定本次任务、终态和金额的一次性二次验证凭证。

1. 查询验证方式：`GET /api/verify/methods?scope=admin.task.reconcile`。
2. 使用现有密码、2FA、Passkey 或 OAuth 验证流程取得 scope 为 `admin.task.reconcile` 的凭证。`context` 必须包含下例四个字段，实际验证方法与已配置的认证方式一致。
3. 在对账请求头发送 `X-Security-Proof`，body 的任务 ID 和金额必须与凭证完全一致。

验证上下文示例（金额单位为系统 quota，不是美元）：

```json
{
  "task_id": "task_example",
  "status": "SUCCESS",
  "quota_before": 1000,
  "quota_after": 800
}
```

对应对账请求：

```json
{
  "status": "SUCCESS",
  "quota_before": 1000,
  "quota_after": 800,
  "confirmation": "task_example"
}
```

只有待对账、尚未结算且不处于提交租约内的任务可操作。`quota_after` 必须介于零和 `quota_before` 之间；确认失败时使用 `FAILURE`，两项金额都必须为零。管理员须先核实上游任务及账单，不能把暂时查不到的任务当作失败。成功操作写入财务差额日志与安全审计，重复确认不会再次结算。

## Redis 故障策略

启用 Redis 时，余额缓存可能包含尚未批量落库的预扣。Redis 不可用或余额同步未完成时，鉴权和预扣返回 HTTP 503、错误码 `quota_cache_unavailable`；鉴权响应带 `Retry-After: 5`。不会回退使用可能偏高的数据库旧余额。

故障路径每进程最多每 30 秒输出一次无凭证告警。运维应监控 Redis 可用性及此错误码，恢复缓存连接和待同步记录后再恢复请求。需要高可用时应配置 Redis 故障转移；该策略没有把错误余额回退作为降级选项。

## 任务凭证与升级要求

任务保存实际提交账号，以便渠道更换密钥后仍能查询原任务。新写入的渠道密钥及提交恢复证据使用 AES-256-GCM 加密。部署前必须配置持久的 `CRYPTO_SECRET`，或配置持久的 `SESSION_SECRET` 作为后备来源；所有读取同一任务库的节点必须使用一致的加密密钥。未配置持久密钥时，任务提交会在预扣和上游请求之前拒绝。

历史明文任务仍可读取，下一次写入时自动加密；不对大任务表执行全表回填或新增列。不要在在途任务尚未处理完时直接更换密钥，当前实现没有多密钥轮换机制。回滚至不支持此封装的旧版本前，应处理在途任务并安排相应数据恢复；旧版本无法直接使用已加密的账号凭证。

## 私域素材配额

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `PRIVATE_ASSET_USER_MAX_COUNT` | `1000` | 每个用户跨全部素材组的素材数量上限，`0` 禁用 |
| `PRIVATE_ASSET_USER_MAX_STORAGE_MB` | `1024` | 每个用户保存的原件容量上限，单位 MiB，`0` 禁用 |

素材创建事务再次检查累计配额，同用户不同组并发上传不能各自突破上限。对象大小保存在独立的 `seedance_asset_sizes` 小表，不给现有素材大表新增大小列。历史本地对象没有大小记录时，每个按单文件上限 50 MiB 保守计入，避免读取真实 OSS 或回填历史对象。已有素材较多的站点应根据该保守值配置容量，或明确禁用容量限制。

外部链接只计入素材数量，不占本站原件容量。删除原件素材会一起删除大小记录；禁用限制期间仍记录新上传对象的大小，重新启用时可准确计算这些对象。新表迁移可重复执行，升级不修改历史任务金额和已有渠道累计用量。

素材引用在解码后检查归属，包含 JSON Unicode 转义和大小写不同的 `asset://`。不属于调用用户、不可用或没有授权映射的媒体引用会被拒绝。
